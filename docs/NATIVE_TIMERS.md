# 原生计时与配置确认窗口

系统校时会改变 UTC 时间；协议间隔、维护等待和确认窗口因此使用单调时钟，日期与审计时间继续使用系统时间。

## 计时语义

- configd 的五秒 SDK 巡检、LACP 的周期发送/邻居超时、RSTP 的学习/收敛与保护计时改用单调时钟。
- LLDP 统计中的最近收发年龄与邻居数量按同一有效期计算，过期但尚未被清理的邻居不会计入当前数量。
- 维护暂停支持单调计时的冻结与恢复；Linux 条件变量等待采用单调截止时间，macOS 开发验证采用相对等待。原有 V2/V3 暂停记录格式仍可读。协议进程重启后不把旧进程的暂停时长加到新建的计时器上。
- 新配置确认记录与对应事务日志同时保存单调截止时间和 Linux boot ID。NTP 前跳/回拨与同一次系统启动中的 configd 重启不改变确认窗口；新一次系统启动不能保留旧的未确认窗口。时钟读取失败不会被当作已到期而触发回滚。
- 确认记录的时间字段必须与已提交日志一致，恢复和清理仍检查原有配置权限与前镜像。旧记录缺少单调字段时保留旧的 UTC 语义；升级必须先结束待确认事务。
- 原生快照返回剩余秒数，Web 缓存和页面按单调经过时间递减。修复设备与浏览器相差一天时确认倒计时显示 `0s`，以及校时后显示异常长窗口的问题。数字归零不会自行宣告回滚，最终状态仍由 configd 给出。

## 验证方法

软件测试覆盖墙钟前跳/回拨、同次启动中的进程重启、不同 boot ID、时钟读取失败、旧记录迁移和正常到期。

`scripts/verify_native_clock.py --evidence <新目录>` 仅在所有数据口确认 Down 时运行：临时修改 LLDP 间隔，在待确认期间重启 configd，检查原确认窗口和 Web 倒计时，再等待回滚并核对配置。它不修改实际系统时间，不重启 switchd，也不替代冷启动或外部流量验收。
