# 硬件验收方法

每次部署应建立自己的验收记录。模拟、编译、配置回读和端口 Link Up 分别证明不同层面的行为，不能互相替代。

记录板卡修订、模块料号、MPO 线序、风扇、电源、环境、Debian/内核、源码版本、SDK/驱动摘要及端点条件。B0/A11 独立验收。身份、账户、原始抓包和系统备份应留在受控位置，分享前单独脱敏。

`scripts/acceptance.py collect` 通过 HTTPS 读取状态，使用 `--ca` 指定可信证书，不跳过 TLS 校验；密码交互输入。模拟模式必须显式指定 `--allow-simulator`，输出始终标注为模拟。

## 验收项

| ID | 场景与操作 | 通过证据 |
|---|---|---|
| ID-01 | PCI subsystem、VPD、板级映射和 OBT/风扇身份 | 原始只读库存、物料照片、标明端口的线缆图 |
| EPL-01 | 六个 EPL 分别测试100G、40G、4×25G、4×10G及25/10混合速率 | 每个物理 Lane 的回读、对端链路和双向报文 |
| EPL-02 | 每个 EPL 至少100次在线切换，其余组持续双向发流 | SDK事件、对端链路事件、逐流序号/丢包/CRC，其他组无切换相关链路中断或协议超时 |
| EPL-03 | 待禁用子口仍被VLAN/LAG/MAC/镜像引用 | 预检明确拒绝；用户处理引用后成功 |
| L2-01 | Access/Trunk/PVID/Native、Tagged、入口过滤 | 正向和拒绝流量、隔离和标签抓包 |
| L2-02 | 动态MAC学习/老化、静态MAC、按端口/VLAN清理 | ASIC完整FDB快照及实际目的端口流量 |
| L2-03 | 静态LAG、LACP主动/被动、成员故障 | actor/partner同步、分担、最小成员限制和恢复流量 |
| L2-04 | RSTP三角环、边缘端口、BPDU保护 | 抓包与阻塞/转发状态、收敛时间、无持续环路 |
| L2-05 | LLDP真实入口端口与邻居老化 | 两个不同物理入口的TLV和CPU报文元数据 |
| L2-06 | IGMPv1/v2加入/退出、静态组、router端口 | 外部查询器抓包；共享网段Leave不误删其他接收者，只有显式直连fast-leave立即退出 |
| L2-07 | 广播/组播/未知单播抑制、入出速率、802.1p、SP/DRR | 各流实测速率、队列与策略回读；负向流不受误伤 |
| L2-08 | 单会话本地SPAN的rx/tx/both | 源/目的端口及方向匹配的抓包 |
| RDMA-01 | PCP/DSCP、CNP 分类与混合 Access/Trunk | 外接端点标签/DSCP 抓包、实际 TC 归属、CNP 不受 PFC 暂停；配置回读单独记录 |
| RDMA-02 | IEEE DCBX ETS/PFC/APP 互通 | 逐入口 LLDP 抓包、对端能力与本机固定策略一致；缺失/错误/TTL 0/到期不能显示一致 |
| RDMA-03 | PFC 拥塞、普通业务隔离、持续暂停 | PFC 抓包、硬件暂停/队列/TX 时序与端点重试/丢包；离散采样不作为死锁证明 |
| RDMA-04 | ECN 标记与端点 DCQCN | 需先具备队列水位触发 CE 的硬件/数据路径，再记录 CE/CNP 与速率响应；当前路径不支持 |
| OBT-01 | 逐Lane开关、两个MPO之间及同MPO兄弟EPL位保持 | 12-bit读改写前后值、实际光链路、mux/page恢复 |
| FAN-01 | 核心/OBT温度、PWM与TACH校准 | 原始值、参考温度计/转速计、换算因子、无效值判定 |
| FAN-02 | 12点LUT、升温/降温、4°C回差、四档响应 | 配置与完整寄存器回读、温度/PWM/RPM时序 |
| FAN-03 | 60秒手动测试、核心温度丢失、过热、TACH异常、写不锁存 | 独立计时、满速保护、错误状态；停Web后LUT继续工作 |
| TX-01 | 各阶段失败、确认回复丢失、浏览器断开、Web退出 | configd日志和已核实的终态，未受影响对象不变 |
| TX-02 | 应用/风扇写入/确认过程中服务退出与断电 | 不可变快照/事务日志、冷启动回读；只恢复受影响对象，恢复失败保持该组关闭 |
| STAB-01 | 至少24小时连续运行、5次冷启动、升级/恢复 | uptime和启动ID、日志、CPU/内存、SDK队列延迟、所有步骤完成记录 |
| PERF-01 | 跨MPO双向、不同帧长、6×100G和24×25G | 64/128/512/1518字节及受支持大帧的每流吞吐、CRC、丢包、内部端口预算 |
| L3-01 | 三层页面和写API | 显示尚未启用，API拒绝写入，rpd/FRR未启动 |

`scripts/acceptance.py epl-cycle` 只对显式选择的 EPL 进行 API 切换，默认至少100次，先导出配置，成功或失败后都尝试恢复初始配置。它检查其他 EPL 的管理状态、模式和缓存链路，但1秒遥测无法证明没有瞬时丢包，仍须外部流量发生器、带序号抓包和对端事件记录。脚本不能自动重启交换服务、加载驱动或重置其他 EPL；预检发现依赖时停止，不能替用户删除配置引用。

## 结果格式

逐项记录 `not-run`、`passed`、`failed` 或 `blocked`，附步骤、预期/实际值、时间范围及文件摘要。失败记录原样保留，修复后建立新的运行目录；不要用端口标称速率代替实测吞吐。

跨进程恢复、断电冷启动、持续拥塞和长期稳定性分别建立场景。配置工具执行成功不自动使整项硬件或性能验收通过。
