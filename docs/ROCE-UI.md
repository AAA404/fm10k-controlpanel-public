# RDMA / RoCE 页面与接口

入口为“二层交换 → RDMA / RoCE”，提供概览、配置和诊断。概览分别显示配置状态、设备采样状态及“需独立验收”；不预置其他设备的实验拓扑或性能数字。

## 操作流程

1. 选择分类模式、端口及业务 VLAN，配置数据/CNP DSCP 和 DCBX。
2. 运行只读预检，查看具体字段问题和建议修改；勾选建议后才进入本地草稿。
3. 预览完整差异，提交并完成确认；失败时依据原生事务状态恢复。
4. 在诊断页检查配置一致性、缓冲、计数器和对端策略，再独立进行真实流量验收。

端口依赖、MTU、VLAN 和共享缓冲仍由完整配置模型及原生校验约束。页面不会自动覆盖未保存草稿，离开后停止轮询。采样以设备返回的时间和配置修订判断新鲜度，迟到或不匹配的回复不能冒充当前状态。

## 数据接口

- `GET /api/v1/capabilities`：软件能力、限制和 `roce` 描述。
- `POST /api/v1/roce/preflight`：候选配置的只读预检；`suggestions` 列出字段、旧值、新值及说明。
- `GET /api/v1/operational/roce`：设备实时回读；与完整配置事务接口配合使用。

保留 `roce.qualifications` 数组字段用于兼容，当前返回空数组。诊断 JSON 的 `qualification_records` 同样为空；导出仅包含当前配置、草稿、可用预检及设备采样。它是操作诊断快照，不是流量验收结论。

写入、预检和导出相关操作沿用登录、CSRF 与角色约束。原生读取失败时显示明确错误；模拟结果始终标注为模拟。功能范围见 [RoCE](ROCE.md)。
